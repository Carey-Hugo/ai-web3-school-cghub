## 一、设计目标

**名称：** CGHub Contribution Agent（创客贡献追踪助手）

**解决的问题：**
创客协作中，贡献难以被记录、追踪和量化。人工记录效率低且容易扯皮。

**核心价值：**
AI 辅助记录贡献轨迹，生成结构化报告，但所有链上操作必须经过人工审批才能执行。

## 三、工作流程详解

### 3.1 第一阶段：AI 追踪（自动，无需审批）

```
触发条件：创客开始一个任务协作

步骤 1：任务登记
  创客 A 输入：@cghub-agent 新任务「设计 CGHub logo」
  AI Agent 记录：
    - 任务名称：CGHub logo 设计
    - 参与人：创客 A、创客 B
    - 开始时间：2026-05-27 10:00
    - 预期产出：设计稿（图片文件）

步骤 2：贡献追踪
  AI Agent 持续记录：
    - 创客 A 提交了初稿（图片链接）
    - 创客 B 提供了反馈建议（文本）
    - 创客 A 根据反馈修改了 3 版

步骤 3：AI 生成贡献报告
  AI Agent 自动生成：
    ┌─────────────────────────────────────┐
    │ 任务：CGHub logo 设计              │
    │ 完成状态：✅ 已完成                  │
    │                                     │
    │ 贡献权重分析：                       │
    │  • 创客 A：80%（主设计+执行）       │
    │  • 创客 B：20%（反馈建议）          │
    │                                     │
    │ 贡献明细：                           │
    │  • A：提交初稿 v1、v2、v3（3次）    │
    │  • A：根据反馈修改 3 次             │
    │  • B：提供文字反馈 4 条             │
    │                                     │
    │ 建议分配比例：A 80% / B 20%         │
    └─────────────────────────────────────┘
```

### 3.2 第二阶段：人工审批（必须）

```
审批人：项目负责人或合伙人委员会

创客 A 收到通知：
  「CGHub logo 设计任务已完成，请审批贡献报告」

审批选项：
  ✅ 批准（同意 AI 建议的分配比例）
  ❌ 驳回（修改分配比例，需说明原因）
  📝 补充（添加遗漏的贡献记录）

若批准 → 进入链上执行层
若驳回 → AI Agent 修订报告，重新提交
```

### 3.3 第三阶段：链上存证（多签后执行）

```
审批通过后，AI Agent 调用 CGHub 合约：

  // 伪代码
  cgHubContract.recordContribution(
    taskId: "logo-design-001",
    contributors: [A_address, B_address],
    weights: [80, 20],
    proof: ipfs_hash_of_report,
    approver: committee_multisig
  )

触发 Safe 多签流程：
  2/3 签名人批准 → 合约写入成功
  链上事件：ContributionRecorded(taskId, contributors, weights)
```

## 四、权限控制策略

### 4.1 AI Agent 的权限边界

```
┌──────────────────────────────────────────────────────────┐
│                   AI Agent 权限矩阵                       │
├──────────────────┬───────────────┬───────────────────────┤
│ 操作             │ 权限          │ 条件                   │
├──────────────────┼───────────────┼───────────────────────┤
│ 记录任务         │ ✅ 可执行     │ 自动                   │
│ 追踪贡献行为     │ ✅ 可执行     │ 自动                   │
│ 生成报告         │ ✅ 可执行     │ 自动                   │
│ 发起链上交易     │ ❌ 禁止       │ 需要多签               │
│ 修改分配比例     │ ❌ 禁止       │ 需要人工审批           │
│ 转账/提款        │ ❌ 禁止       │ 需要多签               │
│ 删除贡献记录     │ ❌ 禁止       │ 需要多签+争议仲裁       │
└──────────────────┴───────────────┴───────────────────────┘
```

### 4.2 权限实现机制

```solidity
// Smart Account 权限控制（伪代码）
contract CGHabContributionAgent {
    
    // AI Agent 的操作权限
    function recordContribution(...) external onlyAI {
        // AI Agent 可以调用这个
        // 但实际写入需要多签
    }
    
    function initiateDistribution(...) external onlyAI {
        // AI Agent 发起分配提案
        // 提案进入多签审批队列
    }
    
    // AI Agent 无法直接操作的功能
    function executeTransfer(...) external onlyMultisig {
        // 只有多签才能执行真正的转账
    }
}
```

### 4.3 紧急情况处理

```
场景：AI Agent 生成错误的贡献报告
处理流程：
  1. 人工审批时发现 → 驳回，AI 修订
  2. 恶意篡改检测 → 链上版本 vs AI 报告对比
  3. 争议升级 → 合伙人委员会仲裁

场景：AI Agent 被恶意利用
处理流程：
  1. AI Agent 私钥泄露 → Safe Guardian 机制恢复
  2. 异常操作检测 → 自动暂停 AI 操作权限
  3. 事后审计 → Etherscan 查所有历史调用
```

## 六、核心结论

**W1-06 设计要点：**

1. **受控的核心 = 权限边界清晰**
   - AI 只能追踪和报告，不能直接操作链上资产
   - 所有链上操作必须经过多签审批

2. **人工审批不可绕过**
   - AI 是助手，不是决策者
   - 审批人是最终责任人

3. **CGHub 方向一致**
   - 直接服务于"贡献被记录、价值合理分配"的核心矛盾
   - 可作为 CGHub MVP 的核心功能演示

4. **技术可行性高**
   - AI 追踪：LLM + Context 即可实现
   - 链上存证：现有智能合约技术
   - 多签：Safe 标准方案
