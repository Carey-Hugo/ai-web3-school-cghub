# W2-03：x402 Paywall + CAW Agent 自动支付闭环

## 一、核心概念定义

### x402 协议：支付证明机制

| 对比项 | 直接转账 | x402 支付证明 |
|--------|---------|--------------|
| 验证速度 | 慢（等链上确认 12秒+）| 快（毫秒级验签名）|
| 执行方式 | 实时链上转出 | 预签数据，验签名即可 |
| 可撤回性 | 转出不可撤回 | 签名有过期时间，可失效 |
| 信任来源 | 链上确认不可篡改 | 链上签名数据不可伪造 |

**x402 本质：把「付费证明」标准化，让 Agent 不带现金、带证明来。**

---

### CAW：Cobo Agentic Wallet

CAW = Cobo 出品的 AI Agent 专用智能合约钱包。

| 能力 | 说明 |
|------|------|
| 封装接口 | 把复杂操作封装成简单 API，Agent 调用门槛低 |
| Smart Account | 智能合约钱包，Agent 无私钥 |
| 自动执行限制 | 超出 Session Key 范围的操作，合约直接拒绝 |

## 二、三角色分工

```
┌─────────────────────────────────────────────────────────┐
│                     User（用户）                        │
│   设定 Session Key 边界：币种 + 金额上限 + 有效期        │
└─────────────────────────┬───────────────────────────────┘
                          │ 授权写入 Smart Account
                          ▼
┌─────────────────────────────────────────────────────────┐
│  CAW（Cobo Agentic Wallet）                              │
│   负责「能付钱」— 封装接口，Agent 可调用                 │
└─────────────────────────┬───────────────────────────────┘
                          │ 发起 x402 请求
                          ▼
┌─────────────────────────────────────────────────────────┐
│  x402 Paywall（商户）                                    │
│   负责「验证付过钱」— 验签名，解锁内容                   │
└─────────────────────────────────────────────────────────┘
```

## 三、完整自动支付闭环

**场景：用户授权 Agent 购买课程，Agent 自动完成全流程**

| 步骤 | 执行方 | 动作 |
|------|--------|------|
| 1 | User | 签署 Session Key，设定边界：单笔 ≤ 0.01 ETH |
| 2 | User | 将 Session Key 授权给 Agent |
| 3 | Agent | 接收任务：用户要买 AI 课程 |
| 4 | CAW | Agent 调用 CAW 接口，发起 x402 请求 |
| 5 | x402 商户 | 返回支付金额：0.005 ETH |
| 6 | CAW/Smart Account | 验证：0.005 ETH ≤ 0.01 ETH（限额）→ 通过 |
| 7 | CAW | 生成支付证明（预签名数据） |
| 8 | x402 商户 | 验证支付证明签名 → 有效 |
| 9 | x402 商户 | 解锁课程内容 |
| 10 | Agent | 收到内容 → 返回给用户 |

**全程无人工干预，无私钥暴露，边界自动执行。**

## 四、限制执行机制

**谁来确保 Agent 在合法范围内付钱？**

```
用户设定边界（币种 / 金额 / 有效期）
        ↓
写入 Smart Account 合约（自动执行）
        ↓
Agent 执行操作时 → 合约自动校验
  ├── 在范围内 → 执行
  └── 超范围 → 合约直接拒绝
```

**完整的答案：用户设定 + Smart Contract 自动执行**

## 六、风险分析

| 风险 | 缓解方案 |
|------|---------|
| Smart Contract 漏洞 | 使用成熟钱包（Cobo CAW），上线前安全审计 |
| Session Key 被滥用 | 设置有效期 + 金额上限 + 定期轮换 |
| x402 商户拒服务 | Governance 制定白名单规则 |
| Agent 误操作 | 加入预确认机制（大额操作需用户二次确认）|
