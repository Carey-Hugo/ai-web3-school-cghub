## 一、核心定位

CGHub 的 Governance（治理协作）模块回答的核心问题是：**谁来定规则？谁来裁决争议？谁有权力做什么？**

Payment/Commerce 解决"分什么"，Governance 解决"谁来定规则"——两者一体两面，构成完整的 DAO 协作系统。

---

## 二、治理角色体系

| 角色 | 权限 | 产生方式 |
|------|------|------|
| 普通成员 | 提交贡献、查看记录 | 注册即获得 |
| 验证者 | 确认贡献真实性 | DAO 投票选举 |
| 仲裁者 | 裁决贡献争议 | DAO 投票选举 |
| 管理员 | 制定/修改规则 | DAO 投票选举 |

### 角色说明

**普通成员**：所有加入 CGHub 的参与者，可提交贡献、查看自己的贡献记录和收益分配历史。

**验证者**：负责确认贡献的真实性。比如某人说"我写了一份白皮书"，验证者核查后签署确认。验证者是链上信任的基石。

**仲裁者**：裁决争议。当贡献者对归属或评分有争议时，仲裁者介入审理并给出裁决。

**管理员**：负责发起和推动规则修订提案。重大规则变更必须通过 DAO 投票，不能由个人直接修改。

## 三、规则制定流程

### 核心参数

| 参数 | 值 |
|------|-----|
| 提案门槛 | 100 星钻 |
| 讨论期 | 3天 |
| 投票期 | 3天 |
| 通过门槛 | 67%（绝对多数） |
| 法定人数 | 33%（至少 1/3 投票） |

### 流程

```
提案人提交提案（含规则修订内容）
    ↓
系统检查：提案人星钻 ≥ 100？
    ↓ 不符合 → 驳回
    ↓ 符合 → 进入讨论期（3天）
社区在讨论期提出质疑/建议
    ↓
投票期（3天）：星钻持有者投票
    ↓
计票：
  - 投票率 < 33% → 提案无效（法定人数不足）
  - 投票率 ≥ 33% 且 赞成票 ≥ 67% → 提案通过
  - 其他情况 → 提案否决
    ↓
通过后 → 规则自动生效（智能合约执行）
```

### 提案内容要求

每个提案必须包含：
1. 规则修订的具体内容（原条款 → 新条款）
2. 修订原因和背景
3. 预期影响分析
4. 实施时间节点

## 四、争议裁决流程

### 核心参数

| 参数 | 值 |
|------|-----|
| 仲裁者数量 | 3人 |
| 参选门槛 | 100 星钻 |
| 任期 | 3个月 |
| 选举投票期 | 3天 |
| 裁决期限 | 7天内给出裁决 |
| 通过门槛 | 67% |

### 仲裁者选举

```
候选人申请（星钻 ≥ 100）
    ↓
选举投票期（3天）
    ↓
计票：得票前3名 → 当选仲裁者
    ↓
任期3个月 → 期满重新选举
```

### 争议审理流程

```
贡献者提起争议（提交争议描述 + 证据）
    ↓
系统分配至仲裁者池（3名仲裁者）
    ↓
仲裁者共同审理（各自分析证据）
    ↓
仲裁者投票（赞成/反对/弃权）
    ↓
裁决输出：多数意见为裁决结果
    ↓
裁决生效：争议关闭，相关收益/记录更新
```

### 裁决约束

- 仲裁者必须给出书面裁决理由
- 争议双方可在 48 小时内提交补充证据
- 裁决结果不可上诉（进入下一轮争议需支付额外星钻手续费）

## 五、投票权重

**按星钻（TOKEN）持有量分配投票权重。**

示例：
- 持有 100 星钻 → 100 票
- 持有 500 星钻 → 500 票
- 持有 1000 星钻 → 1000 票

这意味着：在规则制定和选举中，星钻越多，话语权越大。

**为什么这样设计：**
- 星钻本身来自贡献记录（贡献越多 → 星钻越多 → 话语权越大）
- 形成了正向激励：认真贡献的人对规则有更大影响力
- 防止恶意操纵：持有大量星钻的人不会希望系统崩溃（他们的利益与系统深度绑定）

## 六、关键设计原则

### 1. 渐进式权力分散
初创阶段（星钻总量少）→ 规则宽松、门槛低
成熟阶段（星钻总量大）→ 规则收紧、门槛提高

### 2. 代码即法律
规则一旦投票通过，立即写入智能合约，自动执行，不依赖人工干预。

### 3. 透明可追溯
所有提案、投票、裁决均链上存证，任何人可查。

### 4. 防止多数暴政
67% 通过门槛 + 33% 法定人数，既保证决策效率，又防止少数人绑架多数人。

## 七、流程总览图

```
【规则制定】
提案 → 讨论(3天) → 投票(3天) → 计票 → 通过(67%,33%) → 生效

【争议裁决】
争议提起 → 仲裁者池(3人) → 审理 → 投票 → 裁决输出 → 执行

【选举】
申请(100星钻) → 投票(3天) → 计票 → 当选(前3名,67%) → 任期3个月
```

## 九、与 Payment/Commerce 的关系

```
贡献者提交贡献
    ↓
验证者确认真实性
    ↓
链上存证 → x402 证明
    ↓
收益分配 → Payment 模块执行
    ↓
若对收益有争议 → 发起争议 → 仲裁者裁决 → Governance 介入
```

Governance 和 Payment 是两个独立运转的模块，但通过争议机制紧密耦合。
