## 一、CGHub 是什么

**CGHub（Creators Galaxy Hub / 创客星球）** 是一个 DAO 协作系统，解决创客经济最核心的问题：

> 一群人协作，贡献怎么记录？价值怎么分配？

**闭环逻辑：**

```
贡献者完成任务 → AI Agent 追踪记录 → 链上存证 → x402 证明
                                                          ↓
                                             智能合约自动分配收益
                                                          ↓
                                             有争议？→ Governance 裁决
```

---

## 二、为什么现在做

### 市场缺口

| 痛点 | 现有方案 | CGHub 的答案 |
|------|----------|-------------|
| 贡献记录靠人工 | 微信群打卡/表格 | AI 自动追踪 + 链上存证 |
| 收益分配靠信任 | 老大说了算/人工对账 | 智能合约预设规则 + 自动执行 |
| 争议靠扯皮 | 没有机制 | DAO 治理投票 + 仲裁者裁决 |
| AI Agent 无法自主支付 | 不能 / 需人工介入 | x402 + Session Key 授权 |

### 差异化：AI 是关键

```
传统平台：人工记录 → 人工审核 → 人工打款（效率低、不透明）
CGHub：    AI 追踪 → 链上存证 → 合约自动分配（透明、可验证）
```

AI 不仅仅是工具，是贯穿全程的执行层：记录贡献、验证时间戳、生成支付证明、执行分配、触发争议。

## 三、W2 研究产出总结

### 问题地图（W2-01）

四个核心问题域：
1. **身份与信任** — AI Agent 能否拥有链上身份？谁能证明它的能力边界？
2. **支付与结算** ← 主线 — 贡献如何被记录？价值如何分配？AI 能否自动触发链上支付？
3. **治理与协作** ← 兼固 — 多方如何共同决策？AI 在治理中扮演什么角色？
4. **安全与隐私** — AI Workflow 的攻击面是什么？如何防止被滥用？

### 最小支付流程（W2-02）

三层权限体系：
- **Session Key（用户授权）** — 设定操作范围：币种、金额上限、有效期、目标合约
- **Smart Contract（自动执行）** — 权限写入合约，超限直接拒绝，无人可绕过
- **Governance（人工监督）** — 规则需要变更时，DAO 投票决定

### x402 + CAW 闭环（W2-03）

AI Agent 自主支付的标准路径：
1. 用户签署 Session Key，设定边界
2. Agent 调用 CAW 接口，发起 x402 请求
3. x402 验证支付证明（毫秒级，非链上确认）
4. 解锁内容/执行分配
5. 全程无私钥暴露，边界自动执行

### Agent Profile（W2-04）

Agent 的「身份证 + 简历」：
- 身份标识（Who）：名字、版本、归属（DAO 地址）
- 能力声明（What）：能记录贡献、验证时间戳、生成 x402 证明
- 边界限制（Constraints）：不能删除记录、不能修改已上链内容、单次分配 ≤ 预算池 3%
- 调用方式（How）：MCP Protocol / REST API / 自然语言对话
- 信任根（Trust Model）：部署需 DAO Token，多签写操作，操作日志链上可查

### Agent 权限策略（W2-05）

```
Profile（说）+ Policy（做）= 可信 Agent

Profile 声明「能做收益分配，限额 $50 以内」
Policy 执行「实际只能操作 $50，超出被合约拒绝」

Profile 写的边界 ≥ Policy 的实际限制（否则 Profile 失信）
Policy 比 Profile 更严格是正常的（安全余量）
```

### Agent 威胁模型（W2-06）

四层纵深防御：
1. **输入层** — 高危词过滤、结构化指令格式、输入长度限制
2. **Agent 层** — Profile constraints 限制、身份标记验证、高风险操作二次确认
3. **工具调用层** — 返回结果签名验证、MCP 身份认证、数据交叉验证
4. **链上层** — Session Key 金额上限、合约白名单、超额多签审批

核心威胁：Prompt 注入、贡献记录篡改（CGHub 独有）。

### Governance 机制（W2-07）

| 治理能力 | 核心参数 |
|----------|----------|
| 规则制定 | 提案门槛 100 星钻，讨论 3 天，投票 3 天，通过 67%，法定 33% |
| 争议裁决 | 3 名仲裁者，任期 3 个月，参选门槛 100 星钻，裁决期限 7 天 |
| 投票权重 | 按星钻持有量（贡献越多 → 星钻越多 → 话语权越大）|

## 四、CGHub 技术架构

### 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│                      身份层                                  │
│           Lens Profile + 个人作品集 + 链上声誉               │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      协作层                                  │
│    AI Agent（贡献追踪）+ Governance（规则制定/争议裁决）    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      价值层                                  │
│      智能合约（贡献记录 + 收益分配）+ x402（支付证明）       │
└─────────────────────────────────────────────────────────────┘
```

### 核心技术组件

| 组件 | 技术选型 | 作用 |
|------|----------|------|
| 链上钱包 | Cobo Agentic Wallet（CAW） | AI Agent 的智能合约钱包 |
| 支付协议 | x402 | AI 自主支付的证明机制 |
| 账户抽象 | ERC-4337 | Smart Account，Agent 无私钥 |
| 贡献存储 | Solidity 智能合约 | 链上贡献记录，不可篡改 |
| 治理机制 | Snapshot + 链上投票 | 规则制定 + 仲裁者选举 |
| 身份协议 | Lens Protocol | 合伙人链上身份 + 作品集 |
