## 📚 今日学习内容

### 主线 · 路径修正与重大突破

#### ✅ 已理解

> **一句话核心理解：**
> Cobo Agentic Wallet 跟普通 WaaS 2.0 是**两套完全独立的产品**。
> 普通 WaaS 走 `portal.cobo.com`（昨天 6/2 我走的那条路是错的）；
> Agentic Wallet 走 `caw` CLI + App 配对，**不经过 Portal**。

**关键知识点：**

1. **Cobo 产品线分布**
   - Cobo WaaS 2.0：传统钱包（资产/MPC/合约钱包），`developers.cobo.com` 文档
   - **Cobo Agentic Wallet**：Agent 专用，`cobo.com/products/agentic-wallet` 文档
   - 两者 API 端点、认证方式、控制台都不同

2. **Agentic Wallet 的"零"路径**
   - 一行命令：`caw onboard --agent-name "..." --wait`
   - 自动创建 Agent + MPC 钱包 + 配 TSS Node
   - 1 分 4 秒完成，钱包 UUID 立刻可用

3. **Pact 协议**
   - Agent 提交"任务" → Pact 定义 Intent / Execution Plan / Policies / Completion Conditions
   - Owner 在 App 审批 → Pact 进入 `active`
   - Agent 拿 pact-scoped API Key → 只能在策略范围内操作

4. **Policy 服务端拦截**
   - 不上链拒绝：`TRANSFER_LIMIT_EXCEEDED` HTTP 403
   - 结构化响应：`code` + `reason` + `details.policy_id`
   - Agent 可基于此做 retry 或通知 Owner

#### 🔗 知识关联

```
Cobo 产品矩阵
  ├─ WaaS 2.0（传统钱包）
  │   ├─ Custodial Wallet（全托管）
  │   ├─ MPC Wallet（机构）
  │   └─ Smart Contract Wallet
  │
  └─ Agentic Wallet（Agent 专用）⭐ 我们用
      ├─ Agent Identity（caw_agent_xxx）
      ├─ MPC Wallet（agent-owned）
      ├─ Pact 协议（任务级授权）
      └─ Policy Engine（服务端策略）
```

**与创客星球(CGHub)的关联：**
> CGHub 收益分配钱包的设计，可以直接套用 Agentic Wallet 的"Agent 持有钱包 + Pact 任务级授权"模式。
> 这比自建合约钱包 + 多签 + 政策引擎省 80% 工作量（AgentVault 架构的现代化版）。

### 操作 4 · 提交 Pact（auto-approved）

```bash
caw pact submit \
  --intent "CGHub Agent: Test 0.001 SETH transfer on Sepolia" \
  --policies '[{
    "name":"sepolia-test-allow",
    "type":"transfer",
    "rules":{
      "effect":"allow",
      "when":{"chain_in":["SETH"],"token_in":[{"chain_id":"SETH","token_id":"SETH"}]},
      "deny_if":{"amount_gt":"0.002"}
    }
  }]' \
  --completion-conditions '[{"type":"tx_count","threshold":"2"}]'
# Pact ID: 21949238-b169-4aea-a750-efcaa42e59e1
# Status: active（未配对 App → 自动批准）
```

## 💡 今日核心洞见

> 今日最有价值的收获：

1. **"产品分清"是技术对接的第一步**
   > WaaS 2.0 和 Agentic Wallet 是两套产品、两个 Portal、两套 API。混用直接卡死。
   > 以后接任何新 SDK，**先找对官方产品线，再看 Quickstart 路径**。

2. **"零路径"在 CLI 里**
   > caw onboard 一行命令 1 分钟跑通，比 Portal 流程快 100 倍。
   > **CLI 是 agent 时代的入口形态**—— Portal 是人类时代的。

3. **"Policy 拒绝不上链"是 MPC + 链下的优势**
   > 传统合约钱包的限额检查是 gas 消耗（先上链再 revert）
   > CAW 的 Policy 是服务端预检（不上链直接 403）
   > **agent 自动化场景，这能省 90% gas 浪费**

4. **App 配对是"加分项"不是"必须项"**
   > 没配对时 Pact auto-approved
   > 配对后才有 Owner 审批环节
   > 黑客松演示阶段不配对也跑得通
