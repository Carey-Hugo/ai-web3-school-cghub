# W2-02：最小支付与商业流程拆解

## 一、核心机制

AI Agent 发起链上支付依赖两个基础设施：

### 1. ERC-4337 / Account Abstraction（账户抽象）

| 角色 | 说明 |
|------|------|
| 普通用户 | EOA（外部拥有账户）+ 私钥签名 |
| Agent 用户 | Smart Account（智能合约钱包），Agent 无私钥，靠「意图签名」授权 |

### 2. Session Key（会话密钥）

- 用户给 Agent 发一张限时门票
- Agent 只能在规定范围内操作（如：只转 USDC，单笔不超 50U）
- 类比：酒店房卡，只能开指定楼层

## 三、x402 协议的作用

**x402 = 把 HTTP 请求「付费化」的标准协议。**

| 对比 | 传统网站 | x402 网站 |
|------|---------|----------|
| 付费方 | 用户手动付款 | Agent 携带支付证明自动请求 |
| 验证方式 | 人工审核 | 链上验证支付证明 |
| 交互对象 | 用户 | Agent（无需知道对方是谁） |

---

## 四、最小支付流程（全链路）

**场景：用户说「帮我买这门 AI 课程」**

| 步骤 | 执行方 | 动作 |
|------|--------|------|
| 1 | Agent | 接收任务：用户要买 AI 课程 |
| 2 | Agent | 调用 x402 接口：`shop.example.com/course/123` |
| 3 | x402 | 返回：需要支付 0.005 ETH |
| 4 | Agent | 检查：金额 ≤ Session Key 限额？ |
| 5 | Agent | 执行：Smart Account 发起链上转账 |
| 6 | x402 | 验证：链上交易确认 → 解锁课程内容 |
| 7 | Agent | 拿到内容 → 返回给用户 |

**全程 Agent 不接触私钥**，靠 Session Key 授权 + x402 协议验证。

## 五、商业价值分析

### 为什么这对 CGHub 重要

**初创合伙人机制：贡献记录 → 价值分配**

| 场景 | 实现方式 |
|------|---------|
| 合伙人完成任务 | Agent 自动记录贡献（链上证明） |
| 贡献转换为权益 | x402 解锁专属内容/工具 |
| 持续参与激励 | Session Key 限额内自动结算 |

## 六、风险与限制

| 风险 | 缓解方案 |
|------|---------|
| Agent 超出授权范围操作 | Session Key 限制：币种 + 金额 + 有效期 |
| x402 商户拒收 | 事前验证商户资质（DAO Governance） |
| 智能合约漏洞 | 使用成熟钱包（如 Cobo Agentic Wallet） |
