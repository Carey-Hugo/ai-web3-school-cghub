## A1 · 大语言模型（LLM）

**一句话理解：** 大语言模型是通过海量文本训练出来的概率模型，能根据输入生成连贯文本，但「会说话不等于理解」。

**四个关键概念：**
| 概念 | 核心要点 |
|------|---------|
| Token | 模型处理文本的基本单位，1个token≈0.75个英文单词≈1-2个汉字。影响成本、速度和上下文长度。 |
| Embedding | 把文本转为向量，语义相似的文本在向量空间里距离近。用于语义搜索、相似度匹配、RAG检索。 |
| Transformer | 现代LLM的核心架构，通过「注意力机制」处理上下文关系，可以并行计算。 |
| Hallucination（幻觉） | 模型生成看似合理但实际错误或虚构的内容。原因：训练数据偏差 + 概率生成机制。 |

**对AI×Web3的意义：** Agent的所有能力（Tool Use、Planning）都依赖LLM，理解LLM能力边界是设计可靠Agent的前提。

## A2 · Prompt（提示词）

**一句话理解：** Prompt是用自然语言约束模型行为的方式，低成本但脆弱，是AI应用的第一层控制手段。

**核心结构（三要素）：**
1. **任务目标** — 你想让模型做什么（写代码/解释概念/翻译）
2. **边界条件** — 约束输出范围（不超过500字/只用中文/不要代码）
3. **输出格式** — 指定格式要求（JSON/Markdown/分点列出）

**对AI×Web3的意义：** CGHub Agent的prompt决定它如何响应用户请求、设计prompt = 设计用户体验。

## A3 · Context（上下文）

**一句话理解：** Context是模型「能看见什么」的空间，决定了它知道多少、信息如何组织。

**四层架构（与记忆系统的对应）：**
| 层次 | 说明 | CGHub应用 |
|------|------|---------|
| System Prompt | 始终驻留的核心框架 | 品牌规范、调性、角色设定 |
| Knowledge Base | 外部知识库，按需检索 | RAG接入、文档检索 |
| Memory | 跨会话记住偏好和历史 | 用户偏好、项目阶段 |
| 即时上下文 | 每轮重新传入 | 当天任务、实时数据 |

**对AI×Web3的意义：** Bridge融合层需要把链上数据引入Agent Context，Context设计直接决定Agent能否获取实时链上状态。

## A4 · RAG（检索增强生成）

**一句话理解：** RAG = 先检索外部知识，再让LLM基于检索结果生成，降低幻觉，让回答可溯源。

**工作流程（四步）：**
```
用户问题 → 检索(Retriever) → 合并到Context → LLM生成 → 带溯源的回答
```

**四个关键技术：**
| 技术 | 作用 |
|------|------|
| Chunking（分块） | 把长文档切成每块500-1000 token的小块，太长精度下降，太短丢失上下文 |
| Vector DB（向量数据库） | 把chunk转成向量存储，语义相似→向量相似→搜得到 |
| Retriever（检索器） | 根据用户问题从向量库找相关chunks（纯向量/关键词/混合三种方式） |
| Rerank（重排序） | 初步检索20条 → 重排 → 选最相关3-5条喂给LLM，提高答案质量 |

**RAG vs 直接塞Context：**
- 直接塞：受token上限限制，适合知识量小的场景
- RAG：可接入无限知识库，可实时更新外部数据，但速度慢

**对AI×Web3的意义：** CGHub的知识库、文档检索、项目历史查询，都依赖RAG架构。

## A5 · Agent（智能体）

**一句话理解：** Agent让模型从「回答问题」进入「多步执行」，但需要边界、日志和失败恢复机制。

**四个核心能力：**
| 能力 | 说明 |
|------|------|
| Tool Use（工具调用） | 模型可以调用外部工具（API、代码执行、文件读写），从纯推理进入实际执行 |
| Planning（规划） | 把复杂任务拆解为多个步骤，按顺序执行 |
| State（状态） | 在多步执行之间保持记忆和上下文，知道自己做到哪一步 |
| Reflection（反思） | 执行后检查结果，判断是否成功、是否需要重试 |

**Agent vs 普通LLM调用：**
| | 普通LLM | Agent |
|--|---------|-------|
| 交互模式 | 问一句答一句 | 多步执行，持续行动 |
| 失败处理 | 无 | 有重试/兜底机制 |
| 状态保持 | 无 | 有中间状态记忆 |
| 执行能力 | 仅推理 | 可调用外部工具 |

**对AI×Web3的意义：** Agent是CGHub智能体商业化的核心技术层——用户发起需求，Agent自动完成：查链上状态 → 调用支付 → 执行合约 → 记录结果。

## A6 · Evaluation（评估）

**一句话理解：** Evaluation是判断AI系统是否「真正可靠」的手段，不是看demo能不能跑，而是看生产环境是否稳定。

**四个核心概念：**
| 概念 | 说明 |
|------|------|
| Harness（评测框架） | 标准化的测试框架，像pytest跑单元测试一样跑AI能力评测 |
| Golden Set（标准答案集） | 人工标注的高质量问答对，用来对比AI输出质量 |
| LLM-as-Judge | 用强模型评价弱模型输出（用GPT-4评价Claude输出） |
| Regression（回归测试） | 每次代码变更后重新跑评测，确保AI能力不退化 |

**对AI×Web3的意义：** 黑客松作品提交前需要Evaluation证明项目「真的能用」，不是PPT。
